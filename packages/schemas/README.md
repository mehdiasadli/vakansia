# `@vakansia/schemas` package

This package contains the `zod` schemas for the database models, enums and module operations.

This is the single source of truth for schemas and validation in the whole project.

## Structure

### `src/db/schemas`

This file is auto-generated by the `prisma-zod-generator` and contains the `zod` schemas for the database models and enums.

To mutate the behavior of the generator, you can edit the `@vakansia/db/prisma/zod-generator/config.json` file.

For documentation on how to use the generator, you can refer to the [prisma-zod-generator](https://omar-dulaimi.github.io/prisma-zod-generator/docs/intro/what-is) docs.

### `src/modules`

This directory contains the `zod` schemas and types for the module operations, e.g. CRUD operations, authentication/authorization, etc.

#### Formatting

Each database model has its own schema folder (and additionally custom folders might be created for specific module operations, e.g. `auth` etc.).

For example:
- `/modules/user/*.ts`
- `/modules/account/*.ts`
- `/modules/organization/*.ts`
etc.

Each folder contains files for each operation on the model.
For example:
- `/modules/user/create.ts`
- `/modules/user/update.ts`
- `/modules/user/delete.ts`
- `/modules/user/find-one.ts`
- `/modules/user/find-many.ts`
- `/modules/user/search.ts`
- `/modules/user/count.ts`
- `/modules/user/exists.ts`
etc.

Each file should be named like `[operation].schema.ts` and should export the `zod` schema and the type for the operation.

For example:
```ts
export const CreateUserInputSchema = UserSchema.pick({
  name: true,
  email: true,
  username: true
}).extend({
  password: z.string().min(1, "Password is required"),
});

export type CreateUserInputType = z.infer<typeof CreateUserInputSchema>;
```

As you can see, the schema should (if possible) extend the database model schema and may add `zod` utilities, e.g. `pick`, `extend`, `refine`, etc.

Since we are using `orpc` for api operations, the schemas should follow `${Operation}InputSchema` and `${Operation}OutputSchema` naming convention.

### Barrel files

Each module folder should have a `index.ts` file that exports all the schemas and types for the module.

Also, root `index.ts` file should export all the schemas and types for the modules, including `db/schemas`.
